Troubleshooting · 2025-11-17

챗봇 SSE 응답 “비어 있음” & 서식 깨짐 문제

1. 현상 요약

  • 프런트에서 챗봇 질문을 보낼 때 서버는 응답했다고 로그가 찍히지만 UI에는 “응답이 비어있어요”가 노출됨.
  • 응답이 보일 때도 줄바꿈과 리스트가 모두 제거되어 가독성이 크게 떨어짐.
  • `**굵게**`, `# 제목` 같은 마크다운 토큰이 그대로 출력되어 디자인을 해친다는 제보.
Impact 유저는 챗봇이 고장났다고 느끼고, 복잡한 서류 안내를 읽기 어려워 민원 전환율이 급락할 수 있음.

2. 원인 분석

프런트 SSE 파서
  1. 서버가 `text/event-stream` 헤더만 사용하고, 본문은 `data:` prefix 없이 순수 텍스트를 전송.
  2. 기존 파서는 `line.trim()`으로 `data:`가 아닌 줄을 버려서 전체 답변이 누락됨.
  3. 라인마다 `trim()`을 두 번 수행해 선행 공백이 사라지면서 리스트/코드 블록 서식이 깨짐.
  4. 버퍼를 합칠 때 줄바꿈을 보존하지 않아 최종 메시지가 한 줄로 뭉치는 현상 발생.
대화 렌더러
  1. `ChatbotConversation`이 모든 응답을 단일 `

    `로 렌더링하여 줄바꿈 없는 벽 텍스트가 됨.

  2. 마크다운 토큰(`*`, `#`)을 인식하지 않아 그대로 노출.

3. 해결 전략

프런트 SSE 수신 개선

  • `extractPayload`에서 `data:`가 없으면 일반 텍스트로 간주해 누락을 방지.
  • 라인 단위 업데이트 시 `appendPayload(payload, true)`를 통해 `\n`을 복원.
  • 마지막 버퍼는 `trimEnd()`만 적용해 서버가 보낸 줄바꿈 구조를 유지.
  • 빈 응답 대비용으로만 `trim()`을 사용해 콘텐트 손실을 막음.

대화 UI 리치 텍스트 처리

  • `renderAssistantContent` 헬퍼를 도입해 문단/리스트를 동적으로 구성.
  • `-`, `*`, `•` 으로 시작하는 줄은 `
    • `로 변환, 나머지는 `

      `에 `
      ` 삽입.

    • 남아 있는 `*`, `#` 토큰은 `replace(/\*+/g, '')`, `replace(/^#+\s*/g, '')`로 제거.

    백엔드 장애 시 임시 데이터 제공

    • `fallbackCivilPetitions` 정적 데이터를 준비해 API가 500을 응답하면 즉시 대체.
    • 간단한 키워드 포함 여부로 검색어를 필터링해 사용자가 빈 화면을 보지 않도록 함.
    • 실시간 API가 회복되면 자동으로 원 데이터를 사용하므로 운영에 영향 없음.

5.2 SSE 이벤트에 `data:`가 없을 때도 읽히도록

새 extractPayload 
const extractPayload = (line: string) => {
  const trimmedLine = line.trimStart()
  if (trimmedLine.startsWith('data:')) {
    const rawPayload = trimmedLine.slice(5)
    return rawPayload.startsWith(' ') ? rawPayload.slice(1) : rawPayload
  }
  return line.trim().length > 0 ? line : null   // 일반 텍스트 스트림 허용
}

서버가 text/event-stream 헤더만 유지한 채 plain text를 보낼 때도 내용이 누락되지 않습니다.

6. 검증

  1. 실제 챗봇 서버(`49.50.138.5:9500/stream-chat`)와 통신해 긴 답변을 요청.
  2. 브라우저 UI에서 스트리밍되는 텍스트가 즉시 보이고, 줄바꿈/리스트가 유지되는지 확인.
  3. 마크다운 토큰이 더 이상 출력되지 않는지 여러 패턴(굵게, 제목, 리스트)을 테스트.
  4. 로컬스토리지 상태 복구 후에도 동일한 포맷이 유지되는지 검증.

7. 배운 점 & 후속 조치

  • 서버-클라이언트 간 스트리밍 규약을 명확히 문서화해야 한다. `data:` 접두어 여부, 종료 토큰 등을 합의.
  • 텍스트 기반 챗봇이라도 최소한의 마크다운 파서를 두면 유지보수가 쉬워진다. 향후 `react-markdown + DOMPurify` 도입 검토.
  • 트러블슈팅 과정을 빠르게 공유해 유사 이슈 발생 시 레퍼런스로 활용.
